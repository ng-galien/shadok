The chart was pulled anonymously from `oci://ghcr.io/ng-galien/shadok/charts/shadok` at version `1.0.0`; both archives matched the release checksums. A fresh Kind 0.32.0 cluster, Kubernetes v1.36.1 on ARM64, pulled all three Shadok images directly from GHCR. Only the baseline application fixture was built locally.

Passed: chart installation and upgrade, Helm connectivity test, CR-only activation, HTTPS through loopback NodePort without port-forward, two-replica file synchronization, failed build preserving the prior revision, successful build publishing the new revision, file addition/deletion, replacement-pod resynchronization, route isolation, and exact Deployment restoration.

This verifies the published ARM64 runtime and macOS ARM64 CLI. Linux AMD64 CLI and local-image Kind tests passed in CI; image manifests include AMD64 and ARM64. It does not establish every corporate proxy/CNI combination, browser Vite HMR, remote Quarkus dev mode, or built-in authentication. The gateway must remain behind the platform's trusted access boundary.

The local `shadok-release-smoke` cluster is retained for inspection with its DevelopmentSession disabled and baseline restored. No professional cluster was accessed.
